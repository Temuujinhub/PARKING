## 1. Тоног төхөөрөмжийн судалгаа (гарын авлагаас батлагдсан зүйлс)

**Юу суурилуулсан:** Winline UX цувралын all-in-one DC цэнэглэгч, доторх 40 kW модультай
(firmware: `BOARD_CCU_A1001 G40_CCU1_CCS_GW40KW_V1.02.05`), CCS холбогчтой.
Тархи нь **TCU** (тооцооны нэгж) + **CCM** (удирдлагын нэгж).

### 1.1 Холболтын боломж — OCPP батлагдсан

`UX ... User Interface Operation Manual` §2.2.7 «OCPP Platform Configuration»-д яг
дараах тохиргоонууд байна — эдгээр нь **OCPP 1.6J-ийн стандарт түлхүүрүүд**:

| HMI дэх нэр | Утга |
|---|---|
| `Server url` | OCPP холболтын хаяг (бидний CSMS) |
| `OCPPId` | Цэнэглэгчийн нэвтрэх ID = `chargePointId` |
| `Device Id` | Сериал дугаар |
| `Auth1 Mode / username / password` | HTTP Basic authentication |
| `SwDoubleOCPP`, `OcppVice Id`, `SerVice url`, `Auth2 *` | **Хоёр дахь платформ** — үйлдвэрлэгчийн платформ дээр үлдээгээд зэрэг манай систем рүү холбож болно |
| `HeartbeatInterval` | Heartbeat давтамж (сек) |
| `WebSocketPingInterval` | WebSocket ping шалгалт (сек) |
| `AllowOfflineTxForUnknownId`, `AuthorizationCacheEnabled`, `LocalAuthorizeOffline`, `LocalPreAuthorize`, `LocalAuthListEnabled`, `StopTransactionOnInvalidId` | OCPP 1.6-гийн стандарт офлайн эрх шалгах түлхүүрүүд |
| `chargermodel`, `chargervendor` | BootNotification-д явуулах утгууд |

§2.2.5-д `[OCPPProto]` = **Standard** эсвэл **Custom1** (StartTransaction-д Start SOC
нэмж явуулдаг хувилбар). → Манай CSMS **хоёуланг** тэсвэрлэх ёстой: `Custom1` үед
нэмэлт талбарууд ирвэл алдаа өгөхгүй, зүгээр хадгална.

### 1.2 Эхлүүлэх 5 арга (§1.2.1)

QR уншуулах · RFID (M1) карт · POS картаар · Plug-and-Charge · Нууц үгээр.
Нэмээд §1.7-д **MAC-аар авто цэнэглэх** (Европын стандартад машин VIN явуулдаггүй тул
MAC-ыг VIN-ий оронд ашиглана, `carinfo.csv` локал сан).

→ Бидний сонголт: **QR** (үндсэн) + **RFID** (ажилтан/гэрээт машинд).
`[1QR code]` / `[2QR code]` тохиргоогоор дэлгэц дээр гарах QR-ыг өөрсдөө тавьж болно —
гэхдээ наасан QR стикер илүү найдвартай (дэлгэц гэмтсэн ч ажиллана).

### 1.3 Цэнэглэх 5 горим (§1.2.2)

1. **Автомат дүүргэх** — BMS удирдана
2. **Хугацаагаар** — зогсох код `1005`
3. **Тоо хэмжээгээр (кВт.ц)** — зогсох код `1006` ← *бидний хэрэгцээнд хамгийн ойр*
4. **SOC зорилтоор** — зогсох код `9011`
5. **Платформоос захиалах (reservation)** — OCPP `ReserveNow`

⚠ 3-р горим нь **HMI дэлгэцээс гараар** тавигддаг. OCPP-оор алсаас «X кВт.ц-д зогс»
гэж хэлэх стандарт талбар байхгүй тул §3.4-ийн watchdog заавал хэрэгтэй.

### 1.4 Тооцооны мэдээлэл

- §2.2.3-д `[Rate/kWh]` + `[currency]` — үнэ **дотооддоо** тавигддаг (₮ валют жагсаалтад
  байхгүй тул дэлгэц дээрх дүн зөв гарахгүй байж магадгүй → `Info Cost Hide`,
  `Info Unit Hide`, `feeModuleshow=off` болгож **дэлгэц дээрх мөнгийг нуух**, төлбөрийг
  зөвхөн манай систем харуулах нь цэвэрхэн).
- §2.4.4-т тоолуурын өгөгдөл: `MeterA_Energy(Wh)`, `GUNA_Power(kW)`, фазын хүчдэл/гүйдэл
  — эдгээр нь OCPP `MeterValues`-аар ирнэ.
- §2.6 «Historical Bills» — TCU дотроо түүх хадгална (тулгалтын нөөц эх сурвалж).
- USB-гээр лог татах заавар (`docs/evcharger/Exporting charging log via a USB drive`)
  — сүлжээ тасарсан үеийн **гар аргын нөхөлт**.

### 1.5 Комиссын гарын авлагаас (Quick Commissioning Guide)

- AC оролт **400VAC ±10%**, QF0 (MCCB) автомат.
- Модуль тус бүрийн хаяг: RM1=00H, RM2=01H, … (10 цэнэглэгчийг **тус бүрд нь** зөв
  хаяглаагүй бол модулиуд зөрчилдөнө).
- Одоогийн байдлаар үйлдвэрээс ирсэн тохиргоо нь **офлайн RFID** горим
  (`CardReader: on`, `Card on/offline: off`) — өөрөөр хэлбэл **одоо платформгүй ажиллаж
  байна**. Манай CSMS-д холбоход энэ тохиргоог өөрчилнө.
- Дэмжлэг: `megan.lin@szwinline.com` (Winline) — OCPP-ийн яг хувилбар, дэмждэг
  мессежийн жагсаалтыг **бичгээр авах** (§9-ийн шалгах жагсаалт).

### 3.3 Хамгаалалт (өмнөх аудитын сургамжтай уялдана)

- Цэнэглэгч бүрт **өөрийн Basic нууц үг** (`Auth1 password`), DB-д `secretbox`-оор
  шифрлэж хадгална (`services/device_auth.py`-ийн загвараар).
- `chargePointId` (URL) ≡ Basic username байх ёстой — өөр бол **403**. Ингэснээр
  нэг цэнэглэгчийн түлхүүрээр өөрийн дүрд орох боломжгүй.
- Нэг `cpId`-д нэг л идэвхтэй холболт (шинэ нь хуучныг хаана) — «in-flight leak»-ийн
  сургамжаар холболтын бүртгэлийг `finally`-д заавал цэвэрлэнэ
  (`parking-inflight-leak` тэмдэглэлтэй ижил алдаа давтахгүй).
- Rate limit: `BootNotification` давтвал exponential backoff.
- Хэрэв 4G ашиглах бол статик IP/APN шаардлагагүй (гарах холболт) — гэхдээ **wss://
  заавал**, `ws://` бүү зөвшөөр.

### 3.4 «Оруулсан дүн дуустал цэнэглэх» — яг яаж

OCPP 1.6-д «энэ хэмжээ эрчим хүч өгөөд зогс» гэсэн команд **байхгүй**. Гурван
давхар хамгаалалт:

1. **Үндсэн (software watchdog).** `ChangeConfiguration` → `MeterValueSampleInterval=10`,
   `MeterValuesSampledData=Energy.Active.Import.Register,Power.Active.Import,SoC`.
   Ирэх `MeterValues` бүрд `energy = meter_now − meter_start` тооцоод
   `energy ≥ energy_limit` бол `RemoteStopTransaction`.
   *Хоцролтын нөөц*: хязгаарын **98%**-д хүрэхэд зогсоох команд явуулна (40 kW дээр
   10 секунд ≈ 0.11 кВт.ц ≈ 90₮ — хэтрэлтийг бид даана, жолоочид хэзээ ч илүү нэхэмжлэхгүй).
2. **Хугацааны хатуу таг.** `SetChargingProfile` (TxProfile) —
   `chargingSchedule.duration = energy_limit_kWh / чадал × 1.3` + `limit` (kW).
   Сүлжээ тасарсан ч цэнэглэгч өөрөө зогсоно.
3. **Локал тохиргоо.** `offlineLimitTime`, `unsettleLimitNums` (§2.2.5) — офлайн үед
   хэдэн тооцоогүй захиалга зөвшөөрөхийг хязгаарлана.

**Санамж:** цэнэглэгчийн тоолуур **Wh** нэгжтэй ирнэ (`MeterA_Energy(Wh)`), бүх
тооцоог **бүхэл Wh**-ээр хийж, зөвхөн харуулахдаа кВт.ц болгоно (float алдаа хуримтлагдахаас
сэргийлнэ — QPay-ийн 0.0001₮ таслалтын сургамж).

### 3.5 Мессежийн урсгал (prepay)

```
Жолооч QR уншина
  └► GET /api/public/ev/{key}/{conn}          → төлөв, ₮/кВт.ц, боломжит дүн
Дүн + дугаар + утас оруулна
  └► POST /api/public/ev/{key}/{conn}/start   → charge_session (PENDING_PAYMENT)
                                              → QPay invoice (QR/deeplink)
QPay callback (PAID)
  └► idTag үүсгэнэ  ──► RemoteStartTransaction(connectorId, idTag)
                    ──► SetChargingProfile (хугацааны таг)
Цэнэглэгч: Authorize(idTag) → Accepted
           StartTransaction → transactionId, meterStart
           StatusNotification: Charging      ──► зогсоолын тоолуур ЗОГСОНО
           MeterValues ×N                    ──► нийтийн хуудсанд live явц
хязгаарт хүрэв / машин дүүрэв / жолооч зогсоов
           StatusNotification: Finishing     ──► зогсоолын тоолуур ҮРГЭЛЖИЛНЭ
                                             ──► idle fee тоолуур эхэлнэ
           StopTransaction → meterStop, reason
  └► Тооцоо хийнэ (§5) → e-Barimt → шаардлагатай бол буцаалт → SMS
```

### 3.6 ⚠ Ачааллын удирдлага — үл тоомсорловол осол

10 × 40 kW = **400 kW**. 400 V, cos φ≈0.98 үед нэг цэнэглэгч ≈ **59 A**,
нийт ≈ **590 A** → ойролцоогоор **500 kVA** трансформаторын бүтэн ачаалал.

- Бодит байдалд 10 машин зэрэг бүтэн чадлаар цэнэглэх нь ховор ч, **боломжтой**.
- Шийдэл: OCPP **Smart Charging** — `SetChargingProfile` (ChargePointMaxProfile)-оор
  талбайн нийт дээд хязгаар тавьж, идэвхтэй цэнэглэлтийн тоонд хуваарилна
  (жишээ: нийт таг 250 kW → 8 машин зэрэг бол тус бүр 31 kW).
- **Заавал батлах:** УБЦТС-тэй байгуулсан гэрээний **гэрээт чадал (кВт)** хэд вэ?
  Хэтэрвэл торгууль + автомат унана. Энэ тоо нь §4-ийн чадлын хураамжийн үндэс.

### 3.7 Найдваргүй сүлжээ / офлайн

- Цэнэглэгч офлайн болбол `LocalAuthorizeOffline` + `AuthorizationCacheEnabled`-ээр
  урьд танигдсан idTag ажиллана — **гэхдээ мөнгө урьдчилж авсан тохиолдолд**
  идэвхжүүлэх нь эрсдэлтэй → `AllowOfflineTxForUnknownId=false` тавина.
- Холболт сэргэхэд цэнэглэгч хуримтлагдсан `StopTransaction`-уудаа дараалуулж
  явуулна → CSMS **давхардлыг `transactionId`-аар шүүх** ёстой (Ontime POS-ийн
  давхардлын сургамж).
- Бүрэн алдагдсан тохиолдолд TCU-гийн «Historical Bills» / USB лог-оос гараар тулгана.

⚠ Эдгээр нь **нийтийн мэдээлэл**. Бодит тооцоог зөвхөн **УБЦТС-тэй байгуулсан гэрээ**
(тарифын ангилал, гэрээт чадал, чадлын хураамжийн ₮/кВт) тодорхойлно. §9-д асуух зүйлс.

### 4.2 Нэг кВт.ц-ийн бодит өртөг (загвар)

| Зардлын мөр | Тооцоо | ₮/кВт.ц |
|---|---|---|
| Эрчим хүчний худалдан авалт | ААН-ийн цагийн тариф (дундаж) | ~280 |
| ДЭХ дэмжлэгийн хураамж | тогтмол | 23.79 |
| AC→DC хувиргалтын алдагдал | ~6% (үр ашиг ≈94%) | ~18 |
| Сул зогсолтын хэрэглээ (сэнс, халаагуур, дэлгэц) | 10 × ~150 Вт × 24ц ≈ **36 кВт.ц/хоног** ≈ 1,080 кВт.ц/сар | ашиглалтаас хамаарна: 10–40 |
| **Чадлын хураамж** (гэрээт кВт × ₮/кВт/сар) | ← **тодорхойгүй, хамгийн эмзэг мөр** | ашиглалт бага үед **50–150** |
| QPay шимтгэл | ~1% | ~8 |
| e-Barimt + SMS | баримт ~0 + SMS 75₮/илгээлт ÷ дундаж захиалга | ~2–5 |
| Тоног төхөөрөмжийн элэгдэл | 10 нэгж, 5 жил, сард X кВт.ц | 50–200 |
| **Нийт өртөг** | | **≈ 450–620** |

**Санал болгох үнэ:** НӨАТ-тай **800₮/кВт.ц** (өдөр), **550–600₮/кВт.ц** (шөнө 22:00–06:00).
- Ашгийн маржин ≈ 25–40%, зах зээлийн 300–1,000₮-ийн дунд байрлана.
- Шөнийн хямдрал нь **ачааллыг оргилоос шилжүүлж** чадлын хураамжийг бууруулна —
  тарифын арбитраж шууд ашиг.
- Үнэ бол **өгөгдөл, код биш**: `ev_price_plans` хүснэгтэд зогсоол/түрээслэгч тус бүрээр,
  цагийн бүсчлэлтэй хадгална (§7.1).

### 4.3 Нэмэлт орлого — idle fee

Цэнэглэж дууссан (`SuspendedEV`/`Finishing`) хойш **N минутын дараа** ₮/мин хураамж.
Санал: 15 минут чөлөөт → дараа нь 300₮/мин (эсвэл зогсоолын хамгийн өндөр тариф ×3).
Энэ бол мөнгө биш, **эргэлтийн хэрэгсэл** — 40 kW цэнэглэгч 1 машиныг ~50 минутад
80% хүргэдэг тул нэг цэнэглэгч өдөрт 8–12 машин үйлчлэх ёстой.

### 4.4 Хууль эрх зүйн туг 🚩

- «Цахилгаан эрчим хүч дамжуулах/түгээх/хангах» үйл ажиллагаа **ЭХЗХ-ны тусгай
  зөвшөөрөл** шаарддаг (Эрчим хүчний тухай хууль). Цэнэглэх үйлчилгээг ихэвчлэн
  «эрчим хүч дахин зарах» биш **үйлчилгээ** гэж үздэг ч энэ **батлагдах ёстой** —
  эсрэг тохиолдолд тарифыг ЭХЗХ тогтооно (өмнө нь 155₮ гэсэн тогтоол дурдагдаж байсан).
- НӨАТ: цэнэглэх үйлчилгээ 10% НӨАТ-тай, e-Barimt-д **зогсоолоос ТУСДАА мөр**
  (өөр барааны нэр/код) байх ёстой.

## 5. Төлбөрийн урсгал ба буцаалт

### 5.1 Урьдчилсан төлбөр (таны хүссэн загвар)

1. QR → дүн сонгоно (жишээ: 10,000 / 20,000 / 50,000₮ эсвэл гараар).
2. `energy_limit_wh = дүн / ₮_per_kWh × 1000` (тухайн үеийн үнээр **түгжинэ** — дунд нь
   тариф солигдвол жолоочид нөлөөлөхгүй).
3. QPay төлөгдмөгц цэнэглэлт эхэлнэ.
4. Зогсох: (а) хязгаарт хүрэв, (б) машин дүүрэв (BMS), (в) жолооч зогсоов, (г) саатал.

### 5.2 Тооцоо

```
actual = round(energy_wh / 1000 × unit_price)  +  idle_fee
remainder = prepaid − actual        # ≥ 0 үргэлж (хязгаар нь хэтрүүлэхийг зөвшөөрөхгүй)
```

### 5.3 Үлдэгдлийг барагдуулах **шатлал** (дарааллаар)

| # | Арга | Хэзээ | Мөнгө хөдлөх үү |
|---|---|---|---|
| 1 | **Зогсоолын төлбөрөөс хасна** | Тухайн машин зогсоолд идэвхтэй session-тэй бол | Үгүй — шууд, шимтгэлгүй ✅ |
| 2 | **Дараагийн удаад үлдээх (үлдэгдэл)** | Жолооч утсаараа сонгосон бол | Үгүй |
| 3 | **QPay буцаалт** | Дээрхийн дараа үлдсэн дүн > босго (жишээ 500₮) | Тийм — **тухайн өдөр** |
| 4 | **Дансаар шилжүүлэг** | QPay буцаалт бүтэлгүйтвэл / өдөр өнгөрсөн бол | Тийм — оператор баталгаажуулна |
| 5 | **Хасалт (write-off)** | Босгоос доош (жишээ <500₮) ба жолооч зөвшөөрсөн | Үгүй |

**Яагаад «тухайн өдөр»**: QPay-ийн буцаалт/цуцлалт нь тооцоо хийгдэхээс өмнө
(ихэвчлэн T+0) л ажилладаг. Тиймээс `charge_refunds` дараалал дээр **өдөрт 2 удаа**
(16:00, 21:00) автомат ажиллагаа + өдрийн эцсийн тайлан.

### 5.4 ⚠ Баталгаажуулах: QPay хэсэгчилсэн буцаалт

- Коллекцод: `DELETE /v2/payment/refund/{payment_id}` — **биетэд дүн байхгүй**
  (`{}`), `cancel`-д зөвхөн `{callback_url, note}`.
- Гуравдагч эх сурвалж «QPay supports both partial and full refunds» гэдэг ч
  **v2 merchant API-д баталгаажаагүй**.
- **Хийх зүйл:** QPay-ээс бичгээр асуух — `refund`-д `amount` дэмждэг үү?
  - Дэмждэг бол → §5.3-ийн 3-р алхам автомат.
  - Дэмждэггүй бол → **бүтэн буцаалт + бодит дүнгээр шинэ нэхэмжлэх** гэдэг нь UX-д
    муу тул 3-р алхмыг **дансаар шилжүүлэг**-ээр солино (жолоочоос дансны дугаар авах
    талбар нэмнэ), эсвэл §5.3-ийн 1/2-р алхмуудыг **үндсэн** болгоно.

### 5.5 e-Barimt

- Баримтыг **урьдчилсан төлбөр дээр биш, ТООЦООНЫ дараа** бодит дүнгээр гаргана
  (үгүй бол буцаалт бүрд баримт цуцлах ажил үүснэ — 2026-08-ны давхар баримтын
  туршлагаас).
- Суваг: msgbill `Үйлчилгээ 3` (одоо бэлэн, `services/msgbill.py`).
- Барааны мөр: «Цахилгаан цэнэглэх үйлчилгээ, X.XX кВт.ц» + шаардлагатай бол
  «Сул зогсолтын хураамж» тусдаа мөр.
- Idempotency-Key = `charge_session.id` (давхар баримт үүсэхгүй).

## 6. SMS мэдэгдэл (msgbill)

**Илэрсэн зүйл:** msgbill Partner API-д (Postman коллекц + developers хуудас)
**цэвэр SMS илгээх endpoint байхгүй**. Байгаа нь:

| Үйлчилгээ | Endpoint | Зориулалт |
|---|---|---|
| 2 | `POST /partner/invoices` (`send:true`) | Нэхэмжлэх үүсгээд **төлбөрийн линк** SMS-ээр (~75₮/илгээлт) |
| 3 | `POST /partner/receipts` | eBarimt (аль хэдийн ашиглаж байна) |
| 4 | `POST /partner/receipts` (device_id) | POS |

→ **Буцаалтын мэдэгдэлд `invoices` ашиглах нь буруу** — жолоочид «төл» гэсэн линк очно.

**Санал болгох зам:**
1. msgbill-ээс **`notify` scope / цэвэр SMS endpoint** хүсэх (тэдний SMS суваг аль хэдийн бий).
2. Хүлээх зуур `services/sms.py` **адаптерийн давхарга** бичих — `send(phone, text)`
   интерфэйстэй, ард нь msgbill (боломжтой болмогц) эсвэл өөр SMS gateway.

3. msgbill-ийн `invoices`-ыг **зөв газарт** нь ашиглана: **B2B/флот цэнэглэлтийн

## 8. Зогсоолын төлбөрөөс чөлөөлөх логик

### 8.1 Механизм — бэлэн байгаа кодыг ашиглана

`services/nested.py`-ийн `pause_session()` / `resume_session(cap)` нь яг таарна:
цэнэглэж эхлэхэд гадна session-ий тоолуур зогсоно, дуусахад үргэлжилнэ,
`transit_max_hours`-тэй ижил **өдрийн дээд хязгаар** аль хэдийн бий.

### 8.2 ⚠ Гол нюанс — «залгаастай» ≠ «цэнэглэж байгаа»

Зөвхөн `StatusNotification: Charging` төлөвт тоолуур зогсоно.
`SuspendedEV` (машин дүүрсэн), `SuspendedEVSE`, `Finishing` → **тоолуур шууд үргэлжилнэ**
+ idle fee эхэлнэ.

Үгүй бол: дүүрсэн машинаа залгаад орхиод **өдөржин үнэгүй зогсох** схем үүснэ —
`parking-fake-exit-scheme` тэмдэглэлтэй яг ижил төрлийн ашиглалт.

### 8.3 Бодлогын хувилбарууд (зогсоол тус бүрээр тохируулна)

| Горим | Тайлбар | Хэнд |
|---|---|---|
| `PAUSE` | Цэнэглэж байх хугацаанд тоолуур зогсоно (өдрийн таг: жишээ 120 мин) | Худалдааны төв (санал) |
| `FREE_MINUTES` | 1 кВт.ц тутамд N минут үнэгүй (жишээ 10 мин/кВт.ц, дээд 180) | Урт хугацааны зогсоол |
| `DISCOUNT` | ≥5 кВт.ц цэнэглэвэл зогсоолын төлбөрөөс 50% | Энгийн, тайлбарлахад хялбар |
| `NONE` | Чөлөөлөлтгүй | Оффисын байр |

### 8.4 Дугаарыг session-тэй холбох

Жолооч QR дээр дугаараа оруулна → тухайн зогсоолын идэвхтэй session-тэй
**fuzzy тааруулна** (`normalize_plate` + Рашбулаг nested-д хийсэн OCR-fuzzy логик).
Олдохгүй бол цэнэглэлт хэвийн явна, зөвхөн чөлөөлөлт хэрэгжихгүй + жолоочид
«зогсоолын бүртгэл олдсонгүй» гэж мэдэгдэнэ (касс дээр гараар зөвшөөрөх боломжтой).

### 8.5 Хадгалалтын эрсдэл (санамж)

10 цэнэглэгч × 10 сек тутам `MeterValues` = **86,400 мөр/хоног**.
`ocpp_messages`-д **7 хоногийн retention** + `charge_session`-д зөвхөн нэгтгэсэн
утга. `parking-disk-retention`-ийн сургамжаар **хэмжээний хамгаалалт эхнээс нь**.

### Phase 3 — QR урьдчилсан төлбөр (2 долоо хоног)

- `charge_sessions`, `ev_price_plans` + тарифын админ UI
- Нийтийн хуудас `/ev/:chargerRef` (Pay.jsx-ийн загвараар): дугаар, утас, дүн,
  QPay QR, live явц (WebSocket)
- QPay callback → RemoteStart; тооцоо → e-Barimt (msgbill, бодит дүнгээр)
- `Payment.kind` + `session_id` nullable миграц
- **Шалгуур:** нэг цэнэглэгч дээр 10 бодит гүйлгээ, e-Barimt тулгалт 100%.

### Phase 4 — Буцаалт + SMS (1 долоо хоног)

- `charge_refunds` дараалал, §5.3-ийн шатлал
- QPay буцаалт (0.4-ийн хариунаас хамаарна) / дансаар шилжүүлэх операторын дэлгэц
- `services/sms.py` адаптер + msgbill холболт
- Өдөрт 2 удаа автомат ажиллагаа + **өдрийн эцсийн буцаалтын тайлан**
- **Шалгуур:** дүүрч зогссон 5 тохиолдолд буцаалт тухайн өдөртөө дуусна, SMS хүрнэ.

### Phase 5 — Зогсоолын чөлөөлөлт + idle fee (1 долоо хоног)

- `parking_exempt_mode` 4 горим + өдрийн таг
- `Charging` ↔ `SuspendedEV` төлөвт суурилсан pause/resume (§8.2)
- idle fee тооцоо, жолоочид SMS/дэлгэцээр анхааруулга
- Дугаарын fuzzy тааруулалт
- **Шалгуур:** дүүрсэн машин залгаастай үлдэхэд зогсоолын тоолуур **ажиллана**.

### Phase 6 — Ачааллын удирдлага + тайлан (1 долоо хоног)

- Талбайн нийт чадлын таг + динамик хуваарилалт (`ChargePointMaxProfile`)
- Тайлан: цэнэглэгч тус бүрийн ашиглалт (%), кВт.ц, орлого, маржин,
  оргил ачааллын график, эрчим хүчний өртөг vs орлого
- Сэрэмжлүүлэг: цэнэглэгч офлайн, алдааны код, тооцоогүй захиалга
- **Шалгуур:** 10 цэнэглэгч зэрэг ажиллахад гэрээт чадлаас хэтрэхгүй.

### Phase 7 — Тэлэлт (дараагийн улирал)

- B2B/флот: RFID карт + сарын нэхэмжлэх (msgbill `Үйлчилгээ 2` + `CompanyInvoice`)
- Бусад зогсоол руу тараах (тариф зогсоол тус бүрээр)
- `ReserveNow` — цэнэглэгч урьдчилан захиалах
- Түншийн API-аар гадны апп-д цэнэглэлт нээх

**Нийт: ~8–9 долоо хоног** (Phase 0-оос хойш), нэг хөгжүүлэгчээр.
