Бүх 6 камер `cgi_poll` (сервер→камер pull, eventManager attach, codes=[All])-оор
холбогдсон, last_seen шинэ. Камер→сервер push шаардлагагүй тул firewall-д
нэмэлт дүрэм хэрэггүй.

10.0.113.x аль сайтынх болохыг шалгах:
```
sudo -u postgres psql -d parking -c "SELECT ps.site_code, d.name, d.ip_address, d.lane_dir FROM devices d JOIN parking_sites ps ON d.site_id=ps.id WHERE d.device_type='camera' AND d.status='active' ORDER BY ps.site_code;"
```

## Камерын сүлжээний онцлог (оношилгоонд чухал)

- **ping ажиллана, tracepath 172.16.100.1-ээс цааш хариугүй** — VLAN хоорондын
  төхөөрөмж ICMP/UDP probe-ыг шүүдэг. Энэ нь хэвийн; «no reply» = эвдрэл БИШ.
- **`curl http://<камер>/` → 000 (хариугүй)** — камерын нэгэн зэрэг зөвшөөрөх
  холболт цөөн бөгөөд ихэнхийг нь манай поллер эзэлдэг тул ШИНЭ богино холболт
  татгалзаж болно. Энэ нь бас хэвийн; камер унасан гэсэн үг биш (last_seen-ээр
  шалгана). Яг энэ шалтгаанаар камерт хандах бүх код ХУВААЛЦСАН keep-alive
  клиент ашигладаг (f5ada3e).
- pmtu 1446 (VLAN хооронд туннел/encap байгааг илтгэнэ).

## ⚠ Гадны хуучин систем (202.131.225.98)

`202.131.225.98`-аас `/api/v1.0/parkings/set-gate-status?GateId=12|14|20|22|23...`
PUT хүсэлтүүд тасралтгүй ирж 404 авч байна — хуучин easy-park платформын
интеграци энэ сервер/NAT руу зааж үлдсэн бололтой. Алдааны мессежүүд нь:
«Gate холболтын төлөв», «Time out», **«Password is not correct»**.

Эрсдэл: тэр систем хаалт/камерт өөрийн нэвтрэлтээр хандсаар байвал Dahua-гийн
олон удаагийн буруу нэвтрэлтийн түгжээг өдөөж, МАНАЙ хаалтны командыг ч
унагаж болно (өмнө нь яг ийм түгжээ 23-30с саатал үүсгэж байсан). Мөн 404
спам лог бөглөнө. **Зөвлөмж:** шилжсэн хаалтуудыг хуучин системээс салгуулах
(вендорт хандах), эс бол nginx дээр энэ IP/замыг 444-өөр хаах.

## Deploy урсгал

1. Test сервер (152.42.235.199 = `test.easy-parking.mn`, DigitalOcean, BARRIER_MOCK=true)
   дээр bundle бэлдэж `/var/www/parking/upd-<commit>-<token>.bundle` болгоно.
2. Windows машинаас HTTPS-ээр татна (production-ы гадагш HTTPS хязгаартай тул).
3. `scp <файл> easyparking@172.16.100.21:/tmp/updNN.bundle`
4. `sudo bash /root/PARKING/deploy/update.sh /tmp/updNN.bundle`
   — DB backup → код → build → restart (~5-10с тасалдал; поллер өөрөө сэргэнэ).

## LED дэлгэц (Monnis, 2026-07-28 — ШИЙДЭГДСЭН)

- Дэлгэц нь `LatticeScreenConfig`-тэй lattice дэлгэц: `LogicScreens` = 64px өргөн,
  16px өндөр **4 логик мөр** (Region [0,0,63,15], [0,16,63,31], ...), өнгө Green.
- `trafficParking.setScreenDisplay {Custom: "текст"}` — мөр таслал (\n, \r\n, \r,
  |, ;) БҮГД үл ойшоогдож 1-р мөрөнд урсдаг (нүдээр батлагдсан).
- **Шийдэл:** `{Custom: ["мөр1","мөр2","мөр3"]}` — жагсаалтын элемент тус бүр
  1/2/3-р мөрөнд тусдаа гарна (нүдээр батлагдсан). `set_screen` одоо олон мөрийг
  жагсаалтаар илгээж, татгалзсан firmware дээр нэг мөрийн fallback ашиглана.
- `trafficParking.setScreenDisplayInfo` гэсэн метод байхгүй (татгалзсан);
  `ledServer.cgi` → 501; `getScreenDisplay/Caps` дэмжигдэхгүй.
- Нэмэлт оношилгоо хэрэгтэй бол: `tools/screen_svc_probe.py <IP>` — камерын бүх
  үйлчилгээ/методыг (system.listService, <svc>.listMethod) болон DHRS бүрэн
  тохиргоог асууна (зөвхөн унших).
