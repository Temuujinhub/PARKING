# Төлбөр ба хаалтны БҮХ дүрэм — судалгаа ба нэгдсэн удирдлага

> Хамрах хүрээ: машин орж ирснээс хойш **төлбөр хэдэн төгрөг болох**, **хаалт
> нээгдэх эсэх**, **өр үүсэх эсэх**-д нөлөөлдөг бүх дүрэм.
> Сүүлд шинэчлэгдсэн: **2026-09-03** (табын бүтэц, жолоочийн аудит нэмэгдсэн).

## 0. Яагаад энэ баримт хэрэгтэй болов

Дүрмүүд дөрвөн өөр газарт тархсан байсан:

| Хаана | Өөрчлөхөд | Хамрах хүрээ |
|---|---|---|
| `.env` (`app/config.py`) | **deploy шаардана** | систем даяар |
| `app_settings` хүснэгт (UI-тай) | шууд | систем даяар (2 түлхүүрт л зогсоолын давхарга байсан) |
| `parking_sites` багана | шууд | зогсоолоор |
| `tariff_templates` | шууд | тарифаар (олон зогсоол хуваалцаж болно) |

Үр дагавар нь хоёр байсан:

1. **Нэг зогсоолд тохирсон утга нөгөөг нь гацаадаг.** Жишээ: `entry_burst_seconds=6`
   нь нэг эгнээтэй зогсоолд зөв, гэхдээ 2 эгнээтэй Маршил дээр хоёр өөр машиныг
   нэг болгож нийлүүлдэг байв.
2. **«Төлбөрөө төлсөн атлаа хаалт нээгдэхгүй» гомдол гарахад** аль тохиргооны
   ХОСЛОЛ буруутайг хэн ч хэлж чаддаггүй байв.

**Шийдэл (2026-09-03):** бүлэг бүрд нийтлэг **зогсоолын давхарга** (`_sites`)
нэмж, тархсан дүрмүүдийг татан нэгтгэж, `Тохиргоо → Төлбөрийн дүрэм` таб дээр
дүрэм бүрийг тайлбартай нь + **зөрчлийн шалгалттай** гаргав.

## 1. Төлбөр тооцох цөм алгоритм

Хэрэгжилт: [`app/billing.py`](../backend/app/billing.py) `calculate_fee()` (мөр 92).
Дуудагдах цэг: [`session_logic.session_fee_info()`](../backend/app/session_logic.py) (мөр 395).

Дараалал **чухал** — дээд дүрэм ажиллавал доод нь огт үзэгдэхгүй:

| # | Дүрэм | Нөхцөл | Үр дүн | Хаанаас |
|---|---|---|---|---|
| 0 | **Төлбөргүй зогсоол** | `site.no_charge` | `0₮`, цаг тоолохгүй | Зогсоолын багана |
| 1 | **Гэрээт (бүртгэлтэй) машин** | `registered_drivers`-д хүчинтэй мөр | `0₮` | Бүртгэлтэй машин хуудас |
| 1a | *Нөхцөлт гэрээт* | `free_first_minutes` эсвэл `free_from/until` эсвэл `contract_type=NIGHT` | бүрэн үнэгүй **биш** — цонх/минут хугацаанаас хасагдаад үлдсэн нь энгийн тарифаар | Жолооч бүрээр + глобал шөнийн цонх |
| 1.5 | **Доторх (nested) зогсоол** | `site.parent_site_id` эсвэл `device.nested_inner` | доторх зогсоолд өнгөрүүлсэн хугацаа **хасагдана** (`transit_max_hours` хүртэл) | Зогсоолын багана |
| 2 | **Үнэгүй эхний хугацаа** | `billable ≤ template.free_minutes` | `0₮` | Тарифын загвар |
| 3 | **Шатлалын үнэ** | `tariff_tiers` (кумулятив) | 60м→1000₮, 120м→2000₮ … | Тариф |
| 4 | **Шатлалаас хэтэрсэн** | сүүлийн шатлалаас хойш | эхэлсэн цаг тутамд `extra_hour_price` | Тариф |
| 5 | **Хоногийн дээд хязгаар** | `daily_cap` | хоног тутмын дүн энэ дүнгээс хэтрэхгүй | Тариф |
| 6 | **Хөнгөлөлт** | `PERCENT` / `FIXED` / `FREE_MINUTES` | эхний хоёр нь дүнгээс, гурав дахь нь **хугацаанаас** хасагдана | Хөнгөлөлт хуудас |
| 7 | **НӨАТ** | `vat_inclusive` | `true` = үнэд багтсан (`vat = total·r/(1+r)`), `false` = дээр нь нэмнэ | `.env` (**глобал**, e-Barimt-тай уялдаатай) |
| — | **Царцсан дүн** | `session.fee_locked` | тарифаас дахин бодохгүй, хадгалсан дүнг буцаана | Суурь хураамжийн зам |

**Онцгой тохиолдол:** `template is None` (тариф холбоогүй) → `0₮`, шалтгаан
«Тариф тохируулаагүй». Энэ бол **чимээгүй орлогын алдагдал** — зөрчлийн
шалгалт үүнийг `HIGH` түвшинд илрүүлнэ.

## 2. Орох хаалт нээгдэх шийдвэрийн мод

Хэрэгжилт: `session_logic.handle_entry()` (мөр 825).

```
уншилт ирлээ
 ├── DEDUP: сүүлийн `dedup_seconds`-д ижил/төстэй дугаар уншигдсан уу
 │     ├── тийм → шинэ бүртгэл ҮҮСГЭХГҮЙ, харин хаалтыг нээнэ
 │     │        (junk уншилт hold-д баригдсан бол нээхгүй)
 │     └── үгүй ↓
 ├── BURST: ЭНЭ КАМЕРТ сүүлийн `entry_burst_seconds`-д уншилт байсан уу
 │     └── тийм → нэг машин гэж үзэж дугаарыг сүүлийн ЗӨВ уншилтаар засна
 ├── ДАХИН ОРОЛТ: өмнөх бүртгэл AWAITING_PAYMENT + exit_device_id-тай юу
 │     └── тийм → хуучныг хааж (create_debt_reentry бол өр үүсгэж) шинийг нээнэ
 ├── ХААЛТТАЙ ЗОГСООЛ (`registered_only`) + гэрээт биш → НЭЭХГҮЙ
 ├── ХАР ЖАГСААЛТ + `block_entry` → НЭЭХГҮЙ
 ├── ФОРМАТ БУРУУ дугаар + policy
 │     ├── open   → нээнэ
 │     ├── hold   → `hold_seconds` хүлээгээд НЭЭНЭ (fail-open)
 │     └── strict → НЭЭХГҮЙ, операторт мэдэгдэнэ
 └── бусад тохиолдолд `device.auto_open` бол НЭЭНЭ
```

## 3. Гарах хаалт нээгдэх шийдвэрийн мод

Хэрэгжилт: `session_logic.handle_exit()` (мөр 1196).

```
уншилт ирлээ
 ├── DEDUP цонхонд байна уу
 │     └── тийм → ЭРХТЭЙ бол хаалтыг дахин нээнэ (`exit_dedup_reopen`)
 │              + эгнээ солилт бол exit_device_id-г шинэчилнэ
 ├── бүртгэл хайх (яг тохирол → OCR ойролцоо → авто сэргээх)
 │     авто сэргээх: `reopen_max_hours` дотор, ЯГ НЭГ нэр дэвшигч,
 │     төлөгдөөгүй, exit_confirmed биш ЭСВЭЛ `fake_exit_minutes`-ээс богино
 ├── бүртгэл ОЛДСОНГҮЙ
 │     ├── гэрээт машин         → ЯМАГТ нээнэ (өртэй байсан ч)
 │     ├── `no_session_fee > 0` → суурь хураамжтай царцсан бүртгэл үүсгэнэ
 │     └── бусад                → «Бүртгэл олдсонгүй», оператор шийднэ
 ├── ЭРТ ГАРАХ: орсноос хойш `min_stay_seconds`-ээс бага → НЭЭХГҮЙ ⭑шинэ
 ├── ӨРТЭЙ: `block_exit_debt_count`-аас дээш → НЭЭХГҮЙ (гэрээтэд үйлчлэхгүй)
 ├── PAID + `now ≤ exit_deadline` (= paid_at + grace_minutes) → НЭЭНЭ
 ├── `fee.is_free` → НЭЭНЭ
 ├── `amount_due ≤ 0` (өмнө нь төлсөн) → НЭЭНЭ
 ├── ДАНС: `wallet_auto_deduct` бол үлдэгдлээс хасна → хүрвэл НЭЭНЭ
 └── бусад → AWAITING_PAYMENT, LED-д дүн, QR/касс хүлээнэ
```

### «Төлсөн атлаа хаалт нээгдэхгүй»-ийн БҮХ шалтгаан

| # | Шалтгаан | Илрэх шинж | Засах газар |
|---|---|---|---|
| 1 | `grace_minutes = 0` эсвэл маш богино | төлбөр төлмөгц дахин нэхэгдэнэ | Тариф → *Төлбөрийн дараах үнэгүй гарах хугацаа* |
| 2 | Хуурамч өр + `block_exit_debt_count` | `debt_blocked` action, DEBT_ALERT | Төлбөрийн дүрэм → өрийн 2 дүрэм |
| 3 | `exit_dedup_reopen` унтраалттай | хаалтны команд амжилтгүй болсны дараа dedup цонх дуустал гацна | Төлбөрийн дүрэм |
| 4 | `reopen_cooldown_sec` хэт урт | араас нь дагаж ирсэн машинд `SKIPPED` мөр үлдэнэ | Төлбөрийн дүрэм |
| 5 | Хаалтны төхөөрөмж бүртгэгдээгүй / камерын `auto_open` унтраалттай | команд огт үүсэхгүй | Төхөөрөмж таб |
| 6 | Эгнээ солилт (гарах-1-д уншигдаад гарах-2-оос гарах) | буруу талын хаалт хөдөлнө | ✅ 2026-09-01-нд засагдсан (626cc22) |
| 7 | `min_stay_seconds` хэт өндөр | эргэж гарах жолооч гацна | Төлбөрийн дүрэм |
| 8 | Тарифын шатлал ахисан (grace дотор ч дүн өссөн) | зөрүү нэхэгдэнэ | Тариф — `daily_cap`/шатлал |

Эдгээрийн **1–5, 7** нь одоо `Тохиргоо → Төлбөрийн дүрэм → Зөрчлийн шалгалт`
хэсэгт зогсоол бүрээр автоматаар илэрнэ.

## 4. Дүрмийн бүрэн бүртгэл

### 4.1 Зогсоол бүрээр тохируулж болох (`Тохиргоо → Төлбөрийн дүрэм`)

| Бүлэг | Түлхүүр | Анхдагч | Юунд нөлөөлнө |
|---|---|---|---|

| Гарах хаалт | `wallet_auto_deduct` | асаалттай | Данснаас автомат хасалт |
| Хаалтны цонх | `dedup_seconds` | 30 с | Давхар уншилтыг нэг машин гэж үзэх цонх |

| Хаалтны цонх | `reopen_cooldown_sec` | 5 с | Хаалт дахин нээх завсар |

| Авто цэвэрлэгээ | `awaiting_hours` | 2 ц | Гарцад уншигдаад төлөөгүйг хаах |
| Авто цэвэрлэгээ | `entry_only_free_hours` | 72 ц | Зөвхөн орох уншилттайг ӨРГҮЙ хаах |
| Авто цэвэрлэгээ | `stale_hours` | 12 ц | Ерөнхий хугацаа хэтэрсэн |
| Авто цэвэрлэгээ | `create_debt` | **унтраалттай** | Гарах уншилтгүйд өр (**таамаг** — 2026-08-12-ны аудитаар 1,786 хуурамч өр) |
| Авто цэвэрлэгээ | `create_debt_unpaid_exit` | асаалттай | Гарцад уншигдаад төлөөгүйд өр (**баримттай**) |
| Авто цэвэрлэгээ | `create_debt_reentry` | асаалттай | Дахин орж ирэхэд өр |
| Авто цэвэрлэгээ | `create_debt_shift_close` | асаалттай | Ээлж хаахад өр |
| Авто цэвэрлэгээ | `create_debt_night_close` | асаалттай | Шөнийн хаалтад өр |

**Дарах дараалал:** `DEFAULTS` → `.env` (зөвхөн 4 түлхүүрт) → `app_settings`
глобал → `app_settings._sites[site_id]`.

**Ерөнхий горим:** табын зогсоол сонгогчийн «Ерөнхий — бүх зогсоолын анхдагч»
сонголт нь `app_settings` глобал утгыг засна (`PUT /api/admin/payment-rules/global`).
Энэ бол дүрмийн ерөнхий утгыг засах **цорын ганц** газар — өмнөх «Авто цэвэрлэгээ»
таб давхар засдаг байсныг 2026-09-03-нд арилгав. Тоон утга `payment_rules.MIN/MAX`
мужид шахагдана.

**«Шөнө үнэгүй» цонх энд БАЙХГҮЙ.** Энэ нь тодорхой машинуудад (NIGHT төрлийн
гэрээт) олгодог нөхцөл тул зогсоолд биш, `Бүртгэлтэй машин` хуудасны 🌙
тохиргоонд харьяалагдана (`driver_type_rules`, глобал).

## 5. Цагийн бүсийн дүрэм (2026-09-03-ны «8 цагийн зөрүү»)

**Шалтгаан нь серверийн цаг БИШ.** Сервер UTC, NTP-тэй, зөв
(`timedatectl` → `Etc/UTC`, synchronized). DB бүхэлдээ **naive UTC**
([`app/timeutil.py`](../backend/app/timeutil.py)-ийн дүрэм).

Зөрүү нь **харуулах давхаргад** байсан — гурван газар UTC мөрийг хөрвүүлэлгүй
шууд зүсдэг байв:

| Газар | Байсан | Болсон |
|---|---|---|
| `ReportTabs.jsx` `hm()` — «өдрийн бүх гүйлгээ» Орсон/Гарсан/Төлсөн | `iso.slice(11,16)` | `fmtHM()` (локал) |
| `ReportTabs.jsx` «Бичилт» таб Орсон/Гарсан | `iso.slice(5,16)` | `fmtMDHM()` |
| `reports_excel.transactions_excel()` | `iso.replace("T"," ")[:16]` | `_iso_local()` (+`Төлсөн` багана нэмэгдсэн) |

**Дүрэм цаашид:** backend-ээс ирсэн `*_time` / `*_at` мөрийг **хэзээ ч**
шууд зүсэхгүй — `api.js`-ийн `fmtDate` / `fmtShort` / `fmtHM` / `fmtMDHM`-ийн
аль нэгийг л хэрэглэнэ. Excel/PDF талд `+TZ` заавал нэмнэ.

Шалгах газар: `Систем эрүүл мэнд` хуудасны **«Серверийн цаг»** нүд —
UTC, УБ цаг, `os_tz` болон зөрүүг харуулна. `os_tz ≠ Etc/UTC` бол шар
анхааруулга гарна (тэр үед `datetime.now()` хэрэглэсэн зам чимээгүй хазайна).

## 5.1 Тохиргооны табуудын бүтэц (2026-09-03)

| Таб | Юу | Яагаад энд |
|---|---|---|
| Зогсоол | Зогсоолын бүртгэл, тариф холболт, багана-дүрэм (no_charge, registered_only…), nested | «ЮУ байгаа» — бүтэц |
| Төхөөрөмж | Камер/хаалт/POS + **«Хаалтыг баталгаажуулах»** (`POST /devices/verify-barriers`) | бүтэц |
| LED дэлгэц | Дэлгэцийн мөрүүд | бүтэц |
| **Төлбөрийн дүрэм** | БҮХ шийдвэрийн дүрэм, ерөнхий + зогсоол бүрээр, зөрчлийн шалгалт, нээх шалтгаан | «ЯАЖ шийдэх» |
| **Автомат ажил** | Камерын эрүүл мэнд, камерын лог нөхөлт, авто цэвэрлэгээг ажиллуулах | «ард нь АЖИЛЛАДАГ» |
| Түрээслэгч / Холболт | Данс, API, түрээслэгч | «ХЭН, ХААШАА» |

Хуучин «Авто цэвэрлэгээ» таб нь дүрэм (цэвэрлэгээний босго, өрийн 5 шилжүүлэгч,
орох дугаарын шалгалт, суурь хураамж) + автомат ажил (камерын эрүүл мэнд, лог
нөхөлт) хольсон бөгөөд Төлбөрийн дүрэмтэй давхцаж байсан тул задлав.

## 6. Хэрхэн ажиллуулах

### Нэг зогсоолын дүрмийг өөрчлөх

`Тохиргоо → Төлбөрийн дүрэм` → зогсоолоо сонгоно → утгыг өөрчилнө → `Хадгалах`.
↺ товч тухайн дүрмийг ерөнхий утга руу нь буцаана.

### API-аар

```bash
# Бүртгэл + глобал утга + зогсоолуудын хураангуй
curl -s -H "Authorization: Bearer $TOKEN" \
  http://127.0.0.1:8000/api/admin/payment-rules

# Нэг зогсоолын үйлчилж буй дүрэм + зөрчлийн шалгалт
curl -s -H "Authorization: Bearer $TOKEN" \
  http://127.0.0.1:8000/api/admin/payment-rules/$SITE_ID

# Зогсоолын давхарга бичих (null = ерөнхий рүү буцаах)
curl -s -X PUT -H "Authorization: Bearer $TOKEN" -H 'Content-Type: application/json' \
  -d '{"exit_rules":{"no_session_fee":3000,"min_stay_seconds":45}}' \
  http://127.0.0.1:8000/api/admin/payment-rules/$SITE_ID
```

### Шинэ дүрэм нэмэхэд

1. `app/services/app_settings.py` → `DEFAULTS[<бүлэг>]`-д мөр нэмнэ
   (утгын **төрөл** нь валидацийн дүрэм болно).
2. Зогсоолоор тохируулах бол `PER_SITE[<бүлэг>]`-д түлхүүрээ нэмнэ.
3. `app/services/payment_rules.py` → `CATALOG`-д **нэр, тайлбар, хэзээ
   үйлчилдэг, хэзээ үйлчлэхгүй**-г бичнэ.
   *(`test_site_rule_overlay.py::test_catalog_covers_every_per_site_key` нь
   энэ алхмыг мартвал шууд унана.)*
4. Хэрэглэх кодод `get_rules(db, <бүлэг>, site_id)` -ээр уншина —
   `settings.*`-ыг ШУУД бүү унш.
5. Машиныг гацаах хослол үүсгэж болох бол `check_conflicts()`-д шалгалт нэмнэ.
