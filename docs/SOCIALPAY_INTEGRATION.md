# SocialPay (Голомт банк) × EasyParking — интеграцийн баримт

Хувилбар 2026-10-14. Эх шаардлага: Голомт банкны «[SP4.0][1.0.0][2026.10.09] Easy Parking»
spec (4.1 машин бүртгэх, 4.2 машин устгах, 4.3 орох/гарах мэдэгдэл) болон «EasyParking x
SocialPay» имэйл (tsogtbayar.j@golomtbank.com 10-09, gantulga_a@golomtbank.com 10-13).

Код: `backend/app/routers/socialpay_router.py`, `backend/app/services/partner_vehicles.py`,
админ: Тохиргоо → Холболт → Гадаад API. Ерөнхий түншийн API: `docs/INTEGRATION_API.md`.

## 1. Зорилго

1. SocialPay хэрэглэгч аппаасаа машинаа EasyParking-д **бүртгүүлнэ / устгана**.
2. Бүртгэлтэй машин манай аль ч зогсоолд **орох, гарах бүрд** EasyParking нь SocialPay-ийн
   webhook-ийг дуудна.
3. SocialPay өөрийн Bill дээр одоогийн зогсолт, **үнэгүй хугацаа**, төлөх дүнг харуулна.
4. **Зогсоолын байршлуудыг** (координат, багтаамж) харуулна.
5. Төлбөрийг SocialPay-ээр авч, EasyParking-д баталгаажуулахад **хаалт автоматаар нээгдэнэ**.

## 3. Нэвтрэлт (EasyParking талын endpoint-ууд)

Spec: «header, body-г EasyParking өөрсдийн дотоод журмаар». Бүх хүсэлтэд толгой:

```
X-API-Key: <түлхүүр>
Content-Type: application/json
```

- Түлхүүрийг EasyParking-ийн админ **Тохиргоо → Холболт → Гадаад API → «Түлхүүр үүсгэх»**-ээр
  үүсгэнэ («Төлбөр батлах эрхтэй» + «Машин бүртгэх + орох/гарах мэдэгдэл (SocialPay)»
  чагттай). Түлхүүр зөвхөн үүсгэх мөчид НЭГ удаа харагдана (DB-д sha256 hash л үлдэнэ) —
  Голомтод нууцлагдсан сувгаар дамжуулна.
- Эрхүүд (scope): `read` (зогсоол/зогсолт лавлах), `pay` (төлбөр батлах → хаалт нээгдэнэ),
  `vehicles` (машин бүртгэх/устгах/bill + мэдэгдэл). SocialPay-ийн түлхүүр `read,pay,vehicles`.
- Буруу түлхүүр → 401; нэг IP-ээс минутад 20+ буруу оролдлого → 429.
- `vehicles` эрхтэй түлхүүр тутам register/delete/bill нийлээд минутад 600 хүсэлт
  (`PARKING_PARTNER_VEHICLE_RATE_PER_MIN`); nginx ч IP тутам `/api/`-д минутад ~600 хүсэлт
  зөвшөөрдөг (хэтэрвэл nginx-ийн 429 нь JSON биш HTML байж болно). Бөөн бүртгэлийг секундэд
  ≤8 хүсэлтээр, 429 ирвэл хүлээж давтана.

## 4. Хариуны ерөнхий хэлбэр

Бүх `/socialpay/*` endpoint spec-ийн хэлбэрээр хариулна (`Content-Type: application/json`):

```json
{"Success": true, "Message": "OK"}
```

Алдаа ч ИЖИЛ хэлбэртэй + зохих HTTP код + тайлбар (`Detail`, Монголоор):

```json
{"Success": false, "Message": "INVALID_PLATE", "Detail": "Дугаарын формат буруу — кирилл үсгээр, ж: 7886УКР"}
```

| HTTP | Message | Утга |
|---|---|---|
| 200 | `OK` | Амжилттай |
| 200 | `ALREADY_REGISTERED` | (register) аль хэдийн бүртгэлтэй — Success=true, давтахад аюулгүй |
| 200 | `NOT_FOUND` | (delete) бүртгэл байхгүй/аль хэдийн устгасан — Success=true, давтахад аюулгүй |
| 200 | `NO_ACTIVE_SESSION` | (bill) машин одоо манай зогсоолд алга — Success=true, `data: null` |
| 400 | `INVALID_JSON` | Body JSON объект биш |
| 400 | `INVALID_PLATE` | `plateNo` байхгүй/формат буруу |
| 400 | `INVALID_USER_ID` | `userId` байхгүй/буруу |
| 401 | `UNAUTHORIZED` | X-API-Key байхгүй/буруу/хаагдсан |
| 403 | `FORBIDDEN` | Түлхүүрт `vehicles` эрх алга |
| 404 | `NOT_REGISTERED` | (bill) энэ хэрэглэгч энэ машиныг бүртгүүлээгүй |
| 409 | `LIMIT_EXCEEDED` | Нэг хэрэглэгч 10-аас олон машин (`PARKING_PARTNER_VEHICLE_MAX_PER_USER`) |
| 429 | `RATE_LIMITED` | Хүсэлтийн хязгаар хэтэрсэн — хэсэг хүлээгээд давтана |
| 503 | `UNAVAILABLE` | Түншийн API идэвхгүй (сервер талын тохиргоо) |

**Дугаарын формат** (`plateNo`): кирилл үсгээр, зай/зураас/жижиг үсэг зөвшөөрөгдөнө
(`"7886 укр"` → `7886УКР`). Зөвшөөрөгдөх хэлбэр: `1234УБА` (4 цифр + 3 үсэг, Ө/Ү/Ё орно),
дипломат `ДК0188`, `1302ДК`, `9914АК`. **Латин үсэг (`7886UKR`, `1234YBA`) татгалзана** —
таамаглаж хөрвүүлбэл өөр хүний машинд бүртгэл үүсч, түүний орох/гарах мэдээлэл задарна.

Талбарын нэрийн том/жижиг үсгийг ялгахгүй (`plateNo` = `PlateNo`); нэмэлт талбарыг үл тооно.

**`userId`**: тоо (`100264`) эсвэл текст (`"100264"`, UUID…) — 1–64 тэмдэгт, үсэг/цифр
болон `. _ - : @ +`. `100264` ба `"100264"` нь НЭГ хэрэглэгч.

## 5. Endpoint-ууд (SocialPay → EasyParking)

### 5.1 Машин бүртгэх — `POST {EasyParkingUrl}/socialpay/register` (spec 4.1)

| Талбар | Төрөл | Заавал | Тайлбар |
|---|---|---|---|
| `plateNo` | string | Тийм | Машины дугаар, ж: `7886УКР` |
| `userId` | string/number | Тийм | SocialPay хэрэглэгчийн unique ID |

```bash
curl -X POST https://test.easy-parking.mn/api/v1/socialpay/register \
  -H "X-API-Key: ТҮЛХҮҮР" -H "Content-Type: application/json" \
  -d '{"plateNo": "7886УКР", "userId": "100264"}'
# → 200 {"Success": true, "Message": "OK"}
# дахин дуудахад → 200 {"Success": true, "Message": "ALREADY_REGISTERED"}
```

- **Идемпотент**: ижил (`plateNo`, `userId`) дахин ирэхэд шинэ мөр үүсгэхгүй, Success=true.
  Timeout-ийн дараа давтахад аюулгүй.
- Нэг хэрэглэгч олон машин (10 хүртэл), нэг машиныг олон хэрэглэгч бүртгүүлж болно.
- Бүртгэл бүр аудитын логт (`PARTNER_VEHICLE_REGISTER`) үлдэнэ.

### 5.2 Машин устгах — `POST {EasyParkingUrl}/socialpay/delete` (spec 4.2)

Body нь 5.1-тэй ижил.

```bash
curl -X POST https://test.easy-parking.mn/api/v1/socialpay/delete \
  -H "X-API-Key: ТҮЛХҮҮР" -H "Content-Type: application/json" \
  -d '{"plateNo": "7886УКР", "userId": "100264"}'
# → 200 {"Success": true, "Message": "OK"}
# бүртгэлгүй/аль хэдийн устгасан → 200 {"Success": true, "Message": "NOT_FOUND"}
```

- Зөвхөн ТУХАЙН хэрэглэгчийн бүртгэл устна (бусад хэрэглэгчийн ижил дугаарын бүртгэл хэвээр).
- **Бүртгэлгүй бол Success=true + `NOT_FOUND`** (404 биш): устгах үйлдэл идемпотент — эхний
  хүсэлт амжилттай болсон ч хариу нь сүлжээнд алдагдвал давтан хүсэлт «алдаа» болж SocialPay-д
  худал бүтэлгүйтэл харагдахгүй. Эцсийн төлөв («бүртгэлгүй») ижил.
- Мөр устахгүй (`deleted_at`) — түүх хадгалагдана. Устгасны дараа тэр машины мэдэгдэл
  (хүлээгдэж байсныг ч) илгээгдэхгүй.

### 5.3 Bill: одоогийн зогсолт, үнэгүй хугацаа, төлөх дүн — `POST {EasyParkingUrl}/socialpay/bill`

Имэйлийн 3-р хүсэлт («Орсон/гарсан үеийн үнэгүй хугацааны мэдээлэл — Bill дээр»).
Body 5.1-тэй ижил. **Зөвхөн тухайн хэрэглэгчийн бүртгүүлсэн машинд** хариулна (бусдын машины
байршил задрахгүй) — эс бол 404 `NOT_REGISTERED`.

```bash
curl -X POST https://test.easy-parking.mn/api/v1/socialpay/bill \
  -H "X-API-Key: ТҮЛХҮҮР" -H "Content-Type: application/json" \
  -d '{"plateNo": "7886УКР", "userId": "100264"}'
```

```json
{"Success": true, "Message": "OK", "data": {
  "plateNo": "7886УКР", "sessionId": "7c1e…", "status": "OPEN",
  "siteCode": "KH", "siteName": "Кэй Эйч хотхон", "address": "…",
  "latitude": 47.9134, "longitude": 106.9312,
  "enteredDate": "2026-10-06T06:12:48.375Z",
  "minutesParked": 40,
  "freeMinutes": 15, "freeUntil": "2026-10-06T06:27:48.375Z", "freeRemainingMinutes": 0,
  "isFree": false, "freeReason": null,
  "totalFee": 1000.0, "paidAmount": 0.0, "amountDue": 1000.0, "currency": "MNT",
  "exitDeadline": null, "paymentId": null, "paymentAmount": null}}
```

| Талбар | Тайлбар |
|---|---|
| `sessionId` | Зогсолтын ID — төлбөрийн intent үүсгэхэд (§7) |
| `status` | `OPEN` (зогсож байна), `AWAITING_PAYMENT` (гарцад ирээд төлбөр хүлээж байна), `PAID` (төлсөн, гарах хугацаа `exitDeadline` хүртэл) |
| `enteredDate` | Орсон цаг, UTC ISO-8601 мс + `Z` |
| `minutesParked` | Одоог хүртэлх нийт минут |
| `freeMinutes` | Үндсэн үнэгүй хугацаа = зогсоолын тарифын «эхний N минут үнэгүй» + гэрээт жолоочийн «эхний N минут» |
| `freeUntil` / `freeRemainingMinutes` | Энэ цагаас өмнө гарвал 0₮ (доторх зогсоолд өнгөрүүлсэн хугацаагаар сунгагдана). Үнэгүй хугацаагүй бол `null` |
| `isFree` / `freeReason` | ОДООГИЙН байдлаар төлбөр 0 эсэх, шалтгаан (тариф, гэрээт, үнэгүй зогсоол, хөнгөлөлт) |
| `totalFee` / `paidAmount` / `amountDue` | Касс, хаалт, бусад wallet-тай ЯГ ИЖИЛ тооцоо (`session_fee_info`); **`amountDue`-г нэхэмжилнэ** |
| `paymentId` / `paymentAmount` | Энэ түншийн хүлээгдэж буй (PENDING) intent байвал |

Машин хэд хэдэн зогсоолд «нээлттэй» бүртгэлтэй бол (жишээ нь хуучин гарах уншилт алдагдсан)
**хамгийн сүүлд орсон** зогсолтыг буцаана. Доторх (nested) зогсоолд байгаа машинд гадна
зогсоолын зогсолт харагдана (төлбөр гадна дээр).

### 5.4 Зогсоолын байршил — `GET|POST {EasyParkingUrl}/socialpay/parkings`

Имэйлийн 4-р хүсэлт. Body шаардлагагүй, ямар ч хүчинтэй түлхүүрээр (`read`).
`/api/v1/sites`-тай ижил эх, camelCase хэлбэр; доторх (хүүхэд) зогсоол жагсаалтад орохгүй.

```json
{"Success": true, "Message": "OK", "sampledAt": "2026-10-14T05:19:00.123456Z", "data": [
  {"siteCode": "KH", "name": "Кэй Эйч хотхон", "address": "…",
   "latitude": 47.9134, "longitude": 106.9312, "googleMapsUrl": "https://maps.app.goo.gl/…",
   "locationAvailable": true, "capacity": 120, "occupied": 85, "free": 35,
   "freeMinutes": 15, "noCharge": false}]}
```

`occupied`/`free` нь нээлттэй зогсолтоос тооцсон ТООЦОО (мэдрэгч биш). `latitude=null`,
`locationAvailable=false` бол координат оруулаагүй (§11).

## 6. Мэдэгдэл (EasyParking → SocialPay) — spec 4.3

`POST {SP_URL}/parking/notification`, auth-гүй (SocialPay манай IP-г whitelist-д бүртгэнэ, §9).

**Орсон** (яг spec-ээр, нэмэлт талбаргүй):

```json
{"data": {"plateNo": "7886УКР", "enteredDate": "2026-10-06T06:12:48.375Z"}}
```

**Гарсан**:

```json
{"data": {"plateNo": "7886УКР", "enteredDate": "2026-10-06T06:12:48.375Z", "exitedDate": "2026-10-06T08:40:02.910Z"}}
```

- Цаг: **UTC**, ISO-8601, яг 3 оронтой миллисекунд + `Z` (spec-ийн жишээтэй ижил).
- Body UTF-8 (кирилл дугаар `\u` escape-гүй), `Content-Type: application/json`.
- Нэмэлт толгой: `Idempotency-Key` = `X-Parking-Event-Id` (мэдэгдэл бүрийн UUID, давталтад
  ижил), `X-Parking-Event: vehicle.entry|vehicle.exit`. SocialPay давхар ирсэн мэдэгдлийг
  `Idempotency-Key`-ээр (эсвэл `plateNo`+`enteredDate`-ээр) ялгаж болно.
- **Амжилт** = HTTP 2xx БА body `"Success": true`. `Message`-ийг логд хадгална.
- Нэг машиныг SocialPay-ийн хэд хэдэн хэрэглэгч бүртгүүлсэн ч мэдэгдэл **нэг л удаа** явна
  (payload-д userId байхгүй — SocialPay дугаараар хэрэглэгчиддээ тараана).

### 6.1 Хэзээ илгээгдэх / илгээгдэхгүй

| Тохиолдол | Шийдвэр | Шалтгаан |
|---|---|---|
| Бүртгэлтэй машин гадна зогсоолд орсон (live камер) | ОРСОН ≈30–40с-ийн дараа | 30с «тогтох» хугацаа: камерын давтан уншилт (burst) дугаарыг засах завсар |
| Орох давтан уншилт, нэг машин хаалтан дээр хэд хэд уншигдсан | Нэг л ОРСОН | Шинэ зогсолт үүсдэггүй; (түнш, зогсолт, үйл явдал) тутам нэг мэдэгдэл |
| Гарсан: камерын гарах уншилт, төлбөр/үнэгүй/гэрээт гарц, оператор/POS-оор гаргасан | ГАРСАН | Бодит гарц (гарах камер/оператор баримттай) |
| Гарсан, гэвч дараа нь «хуурамч гарц» гэж сэргээгдээд (auto-reopen) дахин гарсан | Эхний ГАРСАН л | Нэг зогсолт — нэг ГАРСАН. Үнэн төлөвийг `/socialpay/bill` өгнө |
| Доторх (дамжин) зогсоолд орсон/гарсан | Илгээхгүй | Машин гадна зогсоолдоо хэвээр; гадна орох/гарах л мэдэгдэнэ |
| Гарах уншилтгүй албадан хаалт (12ц phantom, 72ц «зөвхөн орох уншилттай» үнэгүй хаалт, төлсөн-гарцгүй) | **Илгээхгүй** (`socialpay` формат) | Тэр цаг нь машин гарсан цаг биш — худал `exitedDate` илгээхгүй. Машин дахин гарцад уншигдаж сешн сэргэвэл тэр үеийн бодит гарц илгээгдэнэ. `extended` форматад `exitConfirmed:false`-тэй илгээнэ |
| Камерын логоос хэдэн цагийн дараа нөхөж бүртгэсэн (camera_sync) — орсон цаг 2 цагаас хуучин | ОРСОН илгээхгүй | «Саяхан орлоо» гэж хуучин мэдээ спамлахгүй |
| Дээрхийн ГАРСАН (2 цагийн дотор) | ГАРСАН | Шинэ бодит үйл явдал (`enteredDate` бодит) |
| ОРСОН илгээгдсэн машины гарцыг 2+ цагийн дараа нөхөж бүртгэсэн | ГАРСАН (7 хоног хүртэл) | SocialPay-ийн «зогсоолд байна» төлөв хаагдах ёстой |
| Машин бүртгүүлэхээс ӨМНӨ орсон зогсолт | ОРСОН илгээхгүй; гарвал ГАРСАН | Бүртгэлээс өмнөх айлчлал |
| «Зөвхөн бүртгэлтэй» зогсоолд хаалт нээгдээгүй (татгалзсан) | Илгээхгүй | Машин ороогүй |
| Орох уншилтгүй машин гарцад ирж суурь хураамж төлсөн | ОРСОН илгээхгүй, ГАРСАН илгээнэ (`enteredDate` = гарцад уншигдсан цаг) | Орсон цаг тодорхойгүй |
| Бүртгэл устгагдсан, түлхүүр хаагдсан, URL хоосолсон | Илгээхгүй (хүлээгдэж байсан нь `SKIPPED`) | |
| Зогсоолоор хязгаарласан түлхүүр | Зөвхөн тэр зогсоолынх | |

### 6.2 Давталт, дараалал, DEAD

- Хүргэлт **асинхрон outbox** (`partner_vehicle_events`) — хаалт/LPR-ийн урсгалыг хэзээ ч
  хүлээлгэхгүй; SocialPay унасан ч хаалт удаашрахгүй.
- Хугацаа 5с. Амжилтгүй бол **1м, 5м, 15м, 1ц, 2ц, 4ц, 4ц…** — нийт **24 цаг**, дараа нь
  `DEAD` (админ «Түүх» дотроос «Дахин илгээх»).
- **Дараалал**: нэг машины өмнөх мэдэгдэл хүргэгдээгүй байхад дараагийнх нь илгээгдэхгүй
  (ГАРСАН нь ОРСОН-оосоо өмнө очихгүй).
- At-least-once: сүлжээ тасарсан хариу алдагдвал ижил `Idempotency-Key`-тэй дахин ирж болно.

### 6.3 `extended` формат (анхдагч УНТРААЛТТАЙ)

Түлхүүрийн тохиргоонд `extended` сонговол `data` дотор нэмэлт талбар:
ОРСОН — `event`, `sessionId`, `siteCode`, `siteName`, `freeMinutes`, `freeUntil`;
ГАРСАН — `event`, `sessionId`, `siteCode`, `siteName`, `exitConfirmed`, `minutesParked`,
`totalFee`, `isFree`; гарах уншилтгүй албадан хаалт `exitConfirmed:false`-тэй ирнэ.
SocialPay spec-ээс өөр талбарыг хүлээн авахыг баталсны ДАРАА л асаана.

## 7. Төлбөрийн бүтэн урсгал

1. **Зогсолт олох**: `POST /socialpay/bill` (бүртгэлтэй машин) → `sessionId`, `amountDue`.
   (Эсвэл ерөнхий `GET /api/v1/sessions?plate=7886УКР`.)
2. **Intent**: `POST /api/v1/payments` `{"session_id": "<sessionId>"}` →
   `{"payment_id": "…", "amount": 1000, "vat_amount": 91, "status": "PENDING"}`.
   Идэвхтэй PENDING intent байвал ижил `payment_id` буцна; дүн өөрчлөгдсөн бол 409 — өмнөхийг
   confirm эсвэл cancel хийнэ.
3. **Хэрэглэгчээс `amount`-ыг SocialPay талд татна.**
4. **Батлах**: `POST /api/v1/payments/{payment_id}/confirm` `{"transaction_id": "SP-TX-123"}`
   — `amount` **заавал биш** (2026-10-14-ний 422 засвар; байхгүй бол intent-ийн дүн). Ирвэл
   яг тэнцүү байх ёстой. Хариу `{"status": "PAID", …, "ebarimt": {…}}` — зогсолт ТӨЛӨГДӨЖ,
   машин гарцан дээр байвал хаалт ШУУД нээгдэнэ, үгүй бол тарифын «төлбөрийн дараах үнэгүй
   гарах хугацаа»-нд (ихэвчлэн 15 мин) гарахад дугаараар нь нээгдэнэ. e-Barimt автоматаар.
5. Мөнгө татаагүй бол intent-ийг цуцлах: `POST /api/v1/payments/{id}/cancel`
   `{"outcome": "NOT_CHARGED"}`.
6. Төлөв: `GET /api/v1/payments/{id}`.

| Код | Хаана | Утга / үйлдэл |
|---|---|---|
| 400 `Session төлөв буруу` | intent | Зогсолт аль хэдийн хаагдсан — bill-ээ дахин асуу |
| 409 `Үнэ өөрчлөгдсөн` | intent | Хугацаа өнгөрч дүн өссөн — хуучин intent-ийг confirm/cancel |
| 400 `Дүн зөрүүтэй` | confirm | `amount` intent-ийнхээс өөр — хаалт нээгдэхгүй |
| 422 | confirm | `transaction_id` дутуу эсвэл `amount: null`/буруу |
| 409 `…дугаар эсвэл дүн зөрлөө` | confirm | Өмнө өөр transaction_id-аар баталгаажсан |
| 200 `PAID` (давтан) | confirm | Идемпотент — ижил transaction_id-аар давтахад алдаагүй |
| 403 | бүгд | Түлхүүрт `pay` эрх алга / өөр түншийн төлбөр |

Төлбөрийн дэлгэрэнгүй, e-Barimt, төлбөрийн webhook: `docs/INTEGRATION_API.md`.

## 8. Edge case / FAQ

- **Машин гарч яваад буцаж орвол?** Шинэ зогсолт → шинэ ОРСОН. Нэг уншилтын давталт шинэ зогсолт үүсгэхгүй.
- **Доторх зогсоол (100 айлын эмнэлэг, Рашбулаг шороо г.м)?** Зөвхөн гадна зогсоолын орох/гарах.
- **ОРСОН ирээд ГАРСАН огт ирэхгүй бол?** Гарах камер машиныг уншаагүй (албадан хаалт).
  `/socialpay/bill` `NO_ACTIVE_SESSION` бол машин манай бүртгэлд зогсоолд АЛГА. Шинэ ОРСОН
  ирвэл өмнөхийг дууссанд тооцохыг зөвлөнө.
- **Дугаарыг латинаар бичвэл?** `INVALID_PLATE` — хэрэглэгчид кирилл үсгээр оруулахыг харуулна.
- **Камер дугаарыг буруу уншвал?** Мэдэгдэл зөвхөн ЯГ дугаараар — ойролцоо дугаараар
  таамаглаж бусдын машины мэдээг илгээхгүй. Тэр айлчлалын мэдэгдэл ирэхгүй байж болно.
- **Хуучин уншилт (camera_sync) хэдэн цагийн дараа?** §6.1-ийн хүснэгт.
- **Цагийн бүс?** Бүх цаг UTC (`Z`). Улаанбаатар = UTC+8.

## 10. Операторын алхам

TEST (Голомтын UAT) ба PROD тус бүрд:

1. **Түлхүүр**: Тохиргоо → Холболт → Гадаад API → «Түлхүүр үүсгэх» → нэр `socialpay`,
   «Төлбөр батлах эрхтэй» ✔, «Машин бүртгэх + орох/гарах мэдэгдэл (SocialPay)» ✔ → түлхүүрийг
   хуулж Голомтод нууцлагдсан сувгаар өгнө. (Одоо байгаа түлхүүрт: мөрийн «Машин бүртгэл
   идэвхжүүлэх» товч — түлхүүр солигдохгүй.)
2. **Мэдэгдлийн URL**: тэр мөрөнд URL — TEST: `https://parking-uat.golomtbank.com/api/parking/notification`,
   PROD: `https://parking.golomtbank.com/api/parking/notification`; формат `socialpay (spec)`;
   «Хадгалах».
3. **Турших**: «Турших» товч жишээ ОРСОН (`0000ТЕС`) илгээж HTTP код + `Message`-ийг харуулна.
   `ConnectTimeout/ConnectError` → манай IP whitelist-д ороогүй эсвэл байгууллагын firewall
   гадагш хаасан; `HTTP 4xx/5xx` → SocialPay талын URL/формат.
4. **IP-г Голомтод мэдэгдэх** (§9) — PROD-ийн outbound IP-г баталгаажуулсны дараа.
5. **Хяналт**: мөрөнд «N машин · хүлээгдэж буй · DEAD» тоо; «Түүх» — мэдэгдэл бүрийн төлөв,
   HTTP код, SocialPay-ийн `Message`, «Дахин илгээх».
6. Сервер талын тохиргоо (заавал биш, `.env`, `PARKING_` угтвартай): `PARTNER_VEHICLE_NOTIFY`
   (true), `PARTNER_VEHICLE_SCAN_SEC` (10), `PARTNER_VEHICLE_SETTLE_SEC` (30),
   `PARTNER_VEHICLE_ENTRY_MAX_AGE_MIN` (120), `PARTNER_VEHICLE_EXIT_MAX_AGE_MIN` (120),
   `PARTNER_VEHICLE_PAIR_DAYS` (7), `PARTNER_VEHICLE_MAX_PER_USER` (10),
   `PARTNER_VEHICLE_RATE_PER_MIN` (600), `PARTNER_VEHICLE_HTTP_TIMEOUT` (5),
   `PARTNER_VEHICLE_RETRY_HOURS` (24).

Deploy: шинэ хоёр хүснэгт (`partner_vehicles`, `partner_vehicle_events`) + `partner_keys`-д
хоёр nullable багана — startup migration миллисекундэд, хуучин өгөгдөл хөндөхгүй.

## 13. Голомтод тодруулах асуулт

1. **Дугаарын эзэмшлийг хэн баталгаажуулах вэ?** Бид дурын дугаарыг бүртгэж чадна — SocialPay
   хэрэглэгч өөрийнх биш машиныг бүртгүүлбэл тэр машины орох/гарах цаг, байршлыг харна.
   SocialPay талд машины гэрчилгээ/ХУР-аар шалгах уу?
2. Мэдэгдлийн хариуд `Success:false` ирэх боломжит `Message`-үүд (жишээ нь «хэрэглэгч олдсонгүй»)
   — тэдгээрийг давтах уу, шууд DEAD болгох уу? Одоо 24ц давтана.
3. `{SP_URL}/parking/notification`-ийн хариуны хугацаа (бид 5с хүлээнэ) ба давхар мэдэгдлийг
   `Idempotency-Key`-ээр ялгах боломж.
4. Гарах уншилтгүй хаагдсан зогсолтын талаар мэдэгдэл хүсэх үү? (Хүсвэл `extended`
   форматаар `exitConfirmed:false`-тэй.)
5. Bill-ийн талбаруудын нэр/хэлбэр (`amountDue`, `freeUntil` …) таны Bill-д тохирох уу?
6. Хэрэглэгч тутмын машины дээд тоо (10) хангалттай юу? Анхны ачаалалд бөөн бүртгэл
   (хэдэн мянга) хийх үү — хурдны хязгаар минутад 600 (≈10/сек).
7. PROD-д бидний гадагшаа IP-г баталгаажуулсны дараа whitelist-д бүртгэх хугацаа.
